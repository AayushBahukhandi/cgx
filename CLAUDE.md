# cgx — Development Guide

## MANDATORY: Use cgx before opening any file

This repo is indexed by cgx. You MUST query the graph before reading source files.

```bash
cgx summary                          # orient — always run first
cgx query find <name>                # locate any symbol
cgx query blast-radius <function>    # run BEFORE every edit
cgx query deps <node>                # dependencies
cgx hotspots                         # highest-risk files
```

Or via MCP tools if cgx is configured as an MCP server:
`get_repo_summary`, `find_symbol`, `get_blast_radius`, `get_neighbors`, `search_graph`

See `CGX_SKILL.md` for the full reference.

## Project Structure

```
crates/cgx-engine/   — core: Tree-sitter parsing, DuckDB graph, git, clustering
crates/cgx-cli/      — cgx binary and TUI
crates/cgx-mcp/      — MCP stdio server (JSON-RPC 2.0, 10 tools)
packages/web-ui/     — React graph visualizer (Vite, built into web-ui-dist/)
```

## Build & Test

```bash
cargo build --release            # build everything
cargo test                       # run all tests
cargo test -p cgx-engine         # engine tests only
```

## Key Invariants

- `web-ui-dist/` is committed build output — do not analyze it with cgx (excluded by default)
- The graph DB lives at `~/.cgx/<hash>/graph.db` (not in the repo)
- CGX_SKILL.md and AGENTS.md are auto-generated by `cgx analyze` — do not edit manually
- Version bumps must update all three crates: cgx-engine, cgx-cli, cgx-mcp
